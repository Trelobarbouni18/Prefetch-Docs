## Overview

`/brand` uses headless Chrome to visit a page and extract a comprehensive set of brand assets:

- **Colors** — extracted from the logo, optionally from the screenshot and source code
- **Logos** — primary logo URL with dimensions, plus secondary candidates and favicon
- **Fonts** — font family names detected on the page
- **Images** — OG image, Twitter card image, brand assets, screenshot URL
- **Social links** — keyed by platform (twitter, linkedin, github, etc.)
- **Design tokens** (opt-in) — the site's colors by role, its type, and its button and input styles

Everything sits under `data.brand`, the same key `/enrich` uses — so `data.brand.colors` reads identically from either endpoint.

## Color extraction options

| Parameter | What it adds | Where it lands |
|---|---|---|
| *(default)* | Logo colors only | `brand.colors.brand_colors` |
| `screenshotColors=6` | N dominant colors from the page screenshot | `brand.colors.screenshot_colors` |
| `css=true` | Colors defined in CSS stylesheets | `brand.colors.code_colors` |
| `html=true` | Colors defined in HTML attributes | `brand.colors.code_colors` |
| `javascript=true` | Colors defined in JavaScript source | `brand.colors.code_colors` |
| `filterAchromatic=true` | Excludes near-white, near-black, and greyscale results | — |

You can combine any of these. Note that `css`, `html`, and `javascript` all feed the **same** `code_colors` map — it is keyed by nearest named color, not split per source.

## Design tokens

`brand_colors` tells you what a brand's colors are. `designTokens=true` tells you what each one is **for**, read from the page as it renders:

- **Colors by role** — `primary` (the most prominent button's fill), `secondary`, `background`, `text`, `heading`, `link`, plus whether the page is `light` or `dark`
- **Typography** — body and heading font stacks, weights, line height, and the h1–h3 and body sizes
- **Components** — the primary and secondary button (fill, label color, border, radius, weight) and the first text input
- **`border_radius`** — the primary button's rounding, a good proxy for the whole site's

The block lands at `brand.design_tokens`. It is best effort: any field the page gives no reliable answer for is `null`. Requests with `designTokens=true` are never answered from curated data, so they always cost a live render.

```bash
curl "https://api.prefetch.io/brand?url=https://stripe.com&designTokens=true" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

## Example requests

<CodeGroup>

```bash Default
curl "https://api.prefetch.io/brand?url=https://stripe.com" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```bash With screenshot colors
curl "https://api.prefetch.io/brand?url=https://stripe.com&screenshotColors=6" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```bash Full color extraction
curl "https://api.prefetch.io/brand?url=https://stripe.com&screenshotColors=8&css=true&html=true&filterAchromatic=true" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```javascript Node.js
const res = await fetch(
  "https://api.prefetch.io/brand?url=https://stripe.com&screenshotColors=6",
  { headers: { "X-API-Key": process.env.PREFETCH_API_KEY } }
);
const { success, data } = await res.json();
console.log(data.brand.colors.brand_colors[0].hex); // "#635BFF"
console.log(data.brand.logos.primary.url);
console.log(data.brand.fonts.families);
```

</CodeGroup>
