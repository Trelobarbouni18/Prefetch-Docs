## Overview

Queues a check outside the schedule and returns it straight away, with status `queued`. The check runs within seconds; poll [`GET /monitor/{id}/checks/{checkId}`](/api-reference/endpoint/monitor-check) until its status is no longer `queued` or `running`.

Use it to take the first baseline right after creating a monitor, to check a page on demand, or to try a new goal. It works on paused monitors too, and does not move the schedule.

## Example request

<CodeGroup>

```bash cURL
curl -X POST "https://api.prefetch.io/monitor/mon_3f9a1c2b7d4e4f6a8b0c1d2e3f4a5b6c/run" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```javascript Node.js
const base = "https://api.prefetch.io";
const headers = { "X-API-Key": process.env.PREFETCH_API_KEY };

const run = await fetch(`${base}/monitor/${monitorId}/run`, { method: "POST", headers });
const { data: queued } = await run.json();

// Wait for the check, then show only what changed.
let check;
do {
  await new Promise((r) => setTimeout(r, 3000));
  const res = await fetch(`${base}/monitor/${monitorId}/checks/${queued.id}?status=changed`, { headers });
  ({ data: check } = await res.json());
} while (check.status === "queued" || check.status === "running");

for (const page of check.pages) console.log(page.url, page.diff?.text ?? page.diff?.fields);
```

```python Python
import os, time, requests

base = "https://api.prefetch.io"
headers = {"X-API-Key": os.environ["PREFETCH_API_KEY"]}

queued = requests.post(f"{base}/monitor/{monitor_id}/run", headers=headers).json()["data"]

while True:
    time.sleep(3)
    check = requests.get(
        f"{base}/monitor/{monitor_id}/checks/{queued['id']}",
        params={"status": "changed"},
        headers=headers,
    ).json()["data"]
    if check["status"] not in ("queued", "running"):
        break

for page in check["pages"]:
    print(page["url"], page["diff"])
```

The status is `202 Accepted` — the check has been queued, not run.

## One check at a time

A monitor runs one check at a time. If one is already queued or running, this returns `409` and names it — wait for it to finish rather than retrying in a loop. The same rule applies to scheduled checks: one that comes due while the previous is still running is recorded as `skipped_overlap` instead of running alongside it.

## Credits

A manual check is billed exactly like a scheduled one: 1 credit per page fetched (4 on targets tracking `json`), plus 1 per changed page judged against the goal. `estimated_credits` is the upper bound; `actual_credits` on the finished check is what was charged.
