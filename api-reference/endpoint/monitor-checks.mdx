## Overview

Lists the monitor's checks, newest first, with each one's status, page counts and credits. Pass `status` to filter — `status=skipped_no_credits`, say, to see when a key ran dry. Open any check with [`GET /monitor/{id}/checks/{checkId}`](/api-reference/endpoint/monitor-check) to see its pages.

Checks are kept for the monitor's `retention_days` (30 by default) and deleted after that.

## Example request

<CodeGroup>

```bash cURL
curl "https://api.prefetch.io/monitor/mon_3f9a1c2b7d4e4f6a8b0c1d2e3f4a5b6c/checks?limit=10" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```javascript Node.js
const res = await fetch(`https://api.prefetch.io/monitor/${monitorId}/checks?limit=10`, {
  headers: { "X-API-Key": process.env.PREFETCH_API_KEY },
});
const { data } = await res.json();
for (const c of data.checks) console.log(c.finished_at, c.status, c.summary.changed);
```

```python Python
import os, requests

data = requests.get(
    f"https://api.prefetch.io/monitor/{monitor_id}/checks",
    params={"limit": 10},
    headers={"X-API-Key": os.environ["PREFETCH_API_KEY"]},
).json()["data"]
for c in data["checks"]:
    print(c["finished_at"], c["status"], c["summary"]["changed"])
```

## Streaks

Monitors keep no failure counter. To find out how long something has been going on, count the leading run of a status: the list is newest first, so the checks at the top that share a status are the current streak, and the first check with a different status ends it.

`actual_credits` is what each check was charged — 57 here: 18 pages fetched at 3 credits, plus 3 pages judged at 1. Skipped checks are never charged.
