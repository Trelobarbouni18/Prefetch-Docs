## API keys

All Prefetch API endpoints (except `/health` and `/ready`) require an API key. Pass your key in the `X-API-Key` request header:

```bash
curl "https://api.prefetch.io/classify?url=https://example.com" \
  -H "X-API-Key: your_api_key_here"
```

Get your API key from the [dashboard](https://prefetch.io/dashboard).

## Bearer tokens

The `POST /mcp` endpoint also accepts your key as a bearer token, because many MCP clients only offer an `Authorization` field:

```bash
curl -X POST https://api.prefetch.io/mcp \
  -H "Authorization: Bearer your_api_key_here"
```

`X-API-Key` takes precedence if you send both. This applies to `/mcp` only — REST endpoints require `X-API-Key`. See [MCP server](/mcp/overview) for client setup.

## OAuth for apps

Apps that can't hold an API key, such as Claude, ChatGPT, and Claude Desktop, sign you in instead. You approve the app on prefetch.io, and it receives an access token that it sends as a bearer token:

```bash
curl -X POST https://api.prefetch.io/mcp \
  -H "Authorization: Bearer <access token>"
```

You never handle the token yourself: the app gets it, refreshes it, and stores it. Its calls bill the newest active API key on your account (the one on your dashboard) and go through the same key checks below. Access tokens are accepted on the REST endpoints too.

A request with no credentials gets a `401` whose `WWW-Authenticate` header points at `/.well-known/oauth-protected-resource` (or `/.well-known/oauth-protected-resource/mcp` for the MCP server). That's how an app finds where to sign you in.

To remove an app's access, select **Disconnect** under **Connected Apps** on the [dashboard](https://prefetch.io/dashboard). Its next call fails, even if its current token hasn't expired yet.

## Key validation

Every request validates your API key against the following checks, in order:

1. **Present** — key must be included in the header
2. **Not revoked** — key has not been manually revoked
3. **Not expired** — key has not passed its expiry date
4. **Within credit limit** — key has not exceeded its configured credit limit

A request with neither an `X-API-Key` header nor an access token returns `401 Unauthorized`, and so does an expired or disconnected access token. All other failures (invalid, revoked, expired, or over-limit key) return `403 Forbidden`.

<Warning>
Never expose your API key in client-side JavaScript. Proxy requests through your own backend instead.
</Warning>

## Key security best practices

- Rotate keys regularly from the dashboard
- Use separate keys for development and production
- Set a credit limit on each key to prevent unexpected overages
- Revoke compromised keys immediately from the dashboard

## Error responses

| Status | Error message | Cause |
|---|---|---|
| `401` | `"API key required"` | No `X-API-Key` header or access token provided |
| `401` | `"The access token has expired"` | A connected app's token expired; the app refreshes it |
| `401` | `"This connection to Prefetch was disconnected. Reconnect to continue."` | The app was disconnected from the dashboard |
| `403` | `"Invalid API key"` | Key not found in the system |
| `403` | `"API key has been revoked"` | Key was manually revoked |
| `403` | `"API key has expired"` | Key passed its expiry date |
| `403` | `"Credit limit exceeded"` | Key used all its allocated credits |
