n8n workflows are JSON: **copy one of the workflows below and paste it into an empty canvas** (Ctrl+V / ⌘V). Each uses n8n's core nodes only — Code, HTTP Request, Edit Fields, Split Out and Wait.

## Add your API key once

Every HTTP Request node uses a **Header Auth** credential named `Prefetch API key`. Create it the first time you open a pasted workflow: double-click an HTTP Request node → **Credential → Create new**:

| Field | Value |
|---|---|
| Name | `X-API-Key` |
| Value | your Prefetch API key |

Name the credential `Prefetch API key` and the other templates pick it up.

## Enrich a list of domains

Enriches each domain with brand, company and industry data, and keeps the fields a CRM usually wants. Replace the **Domains** node with your source — a Google Sheet, your CRM, a webhook. The HTTP node sends one request at a time (raise the batch size up to your plan's concurrency) and retries what can be retried. 12 credits per domain.

## Batch enrich, resumed by the batch's webhook

For hundreds of domains, one [batch](/api-reference/endpoint/batch) beats hundreds of calls: the workflow starts it with its own resume URL (`$execution.resumeUrl`) as the webhook, sleeps in the **Wait** node until Prefetch calls back with `batch_enrich.completed`, then reads the results and splits them into one item per domain. No polling. 12 credits per domain answered.

## Errors

When a request fails, the HTTP Request node's error output carries Prefetch's error body: `error_code` says what went wrong and `retryable` whether a retry can help. The templates retry automatically (**Settings → Retry On Fail**); for `retryable: false` errors such as `DNS_RESOLUTION_FAILED`, switch the node's **On Error** setting to *Continue (using error output)* and route those items aside. Failed requests are never charged.
