Clay's **HTTP API** enrichment calls any API once per row and lets you map fields from the response into columns. Each recipe below is one HTTP API column.

## Set up the column

In your table: **Add enrichment → HTTP API**. Then, for every recipe:

1. **Method** and **Endpoint** as given below. Type `/` in the endpoint to insert a column's value.
2. **Headers**: key `X-API-Key`, value your Prefetch API key.
3. **Run on a few rows**, then choose **fields to return**: Clay lists the response's fields, and each one you pick becomes its own column.
4. **Rate limit**: keep requests in flight within your plan's concurrency — on Free, 1 at a time (30 a minute); on Starter, up to 10 at a time. Rows that hit the limit fail with `CONCURRENCY_LIMITED` and can simply be re-run; failures are never charged.

## Company name → domain

Most lead lists start with names. `/resolve` turns them into domains, which every other recipe needs.

| Setting | Value |
|---|---|
| Method | `GET` |
| Endpoint | `https://api.prefetch.io/resolve?live=true&name=` + `/Company Name` |

| Field | Response path |
|---|---|
| Domain | `data.results[0].domain` |
| Confidence | `data.results[0].confidence` |

Treat a confidence of **0.8 or above** as the answer. Add a Clay condition to only run the next columns when it is, and review the rest. 1 credit per row from the index, 3 when the live lookup runs.

## Domain → full company profile

One `/enrich` call gives brand, company and industry together — cheaper than three separate calls.

| Setting | Value |
|---|---|
| Method | `GET` |
| Endpoint | `https://api.prefetch.io/enrich?url=` + `/Domain` |

| Field | Response path |
|---|---|
| Company name | `data.company.name` |
| Industry | `data.classification.category` |
| Sub-industry | `data.classification.subcategory` |
| One-line description | `data.classification.tagline_description` |
| Description | `data.classification.description` |
| Logo | `data.brand.logos.primary.url` |
| Brand color | `data.brand.colors.brand_colors[0].hex` |
| Contact emails | `data.company.emails` |
| LinkedIn | `data.company.social_links.linkedin` |
| X / Twitter | `data.company.social_links.twitter` |
| Stock tickers | `data.classification.stock_tickers` |

12 credits per row. Well-known companies are answered from curated data in milliseconds; others take 5–20 seconds while the site is read.

## Industry only, for ICP scoring

When all you need is the segment, `/classify` costs less than half of `/enrich`.

| Setting | Value |
|---|---|
| Method | `GET` |
| Endpoint | `https://api.prefetch.io/classify?url=` + `/Domain` |

Map `data.classification.category` (IAB category, e.g. *Business and Finance*), `data.classification.subcategory` and `data.classification.iab_id`. 5 credits per row.

## Logos without an API call

For a logo to look at, you don't need a column that calls the API at all. Get your publishable token once:

```bash
curl https://api.prefetch.io/logo/token -H "X-API-Key: $PREFETCH_API_KEY"
```

Then add a **formula** column:

```
"https://logo.prefetch.io/" + {{Domain}} + "?token=pk_YOUR_TOKEN&size=128"
```

and set its type to **image**. Logos cost no credits — each plan includes a monthly quota of them — and a domain without a known logo shows a letter mark. See [Logo CDN](/api-reference/endpoint/logo-cdn).

## Thousands of rows

Clay calls the API once per row, so a large table is many requests at your plan's concurrency. When you only need the data once, an alternative is one [batch](/api-reference/endpoint/batch): export the domains, send them to `POST /batch/enrich`, and import the results from `GET /batch/enrich/{id}`. Each domain costs the same 12 credits either way.
