`/enrich` returns everything Prefetch knows about the company behind a URL: its [brand](/company-data/brand), its [company details](/company-data/company) and its [industry](/company-data/classify). The page is loaded once, so it costs less than calling the three separately.

| Approach | Credits | Requests |
|---|---|---|
| `/enrich` | 12 | 1 |
| `/brand` + `/company` + `/classify` | 20 | 3 |

Each block sits under the same key its own endpoint uses: `data.brand`, `data.company` and `data.classification`. Code written for `/brand` or `/classify` reads an `/enrich` response unchanged. The one difference is `social_links`, which sits on `data.company` here and on `data.brand` in `/brand`.

## Example requests

<CodeGroup>

```bash cURL
curl "https://api.prefetch.io/enrich?url=https://stripe.com" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```bash With screenshot colors and CSS
curl "https://api.prefetch.io/enrich?url=https://stripe.com&screenshotColors=6&css=true" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```javascript Node.js
const res = await fetch("https://api.prefetch.io/enrich?url=https://stripe.com", {
  headers: { "X-API-Key": process.env.PREFETCH_API_KEY },
});
const { data } = await res.json();

console.log(data.company.display_name);              // "Stripe"
console.log(data.classification.category);           // "Business"
console.log(data.brand.colors.brand_colors[0].hex);  // "#635BFF"
console.log(data.brand.logos.primary.url);
```

```python Python
import os, requests

r = requests.get(
    "https://api.prefetch.io/enrich",
    params={"url": "https://stripe.com"},
    headers={"X-API-Key": os.environ["PREFETCH_API_KEY"]},
)
data = r.json()["data"]
print(data["company"]["display_name"])        # "Stripe"
print(data["classification"]["category"])     # "Business"
print(data["brand"]["logos"]["primary"]["url"])
```

</CodeGroup>

## Parameters

`/enrich` takes the same options as [`/brand`](/company-data/brand#color-options). Like `/brand`, its parameters are camelCase. Batches and MCP take the snake_case spelling (`screenshot_colors`).

| Parameter | Default | Description |
|---|---|---|
| `url` | required | The site to enrich |
| `screenshotColors` | none | Also sample N dominant colors from a screenshot (2–12) |
| `css` | `false` | Also extract colors from stylesheets |
| `html` | `false` | Also extract colors from HTML attributes |
| `javascript` | `false` | Also extract colors from JavaScript |
| `filterAchromatic` | `false` | Drop near-white, near-black and grey colors |
| `designTokens` | `false` | Add `brand.design_tokens`. See [design tokens](/company-data/brand#design-tokens). |
| `screenshotWidth`, `screenshotHeight` | `1440`, `900` | Viewport for the screenshot used for colors and `screenshot_url` (320–3000) |
| `screenshotFormat` | `jpeg` | `jpeg`, `png` or `pdf` |
| `screenshotFullPage` | `false` | Capture the whole scrollable page |
| `disableAdblocker` | `false` | Turn off the built-in ad blocker |

The screenshot settings here only shape the screenshot `/enrich` takes for itself. To capture pages, use [`/screenshot`](/web-data/screenshot), which has its own options and limits.

## For many domains

Send up to 500 domains as one job with [`POST /batch/enrich`](/jobs/batches). Each domain costs the same 12 credits, and you don't have to manage concurrency yourself.
