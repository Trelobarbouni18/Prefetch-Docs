`/brand` returns a site's brand assets under `data.brand`:

- **Colors:** the brand palette, plus optional colors from a screenshot and from source code
- **Logos:** the primary logo, secondary candidates, favicon and app icons
- **Fonts:** the font families the site uses
- **Images:** the Open Graph and Twitter images, brand assets and a screenshot
- **Social links:** profile URLs, keyed by platform
- **Design tokens** (opt-in): what each color is for, the type, and button and input styles

`data.brand` is the same block [`/enrich`](/company-data/enrich) returns, so `data.brand.colors` reads the same from either one.

## Example requests

<CodeGroup>

```bash Default
curl "https://api.prefetch.io/brand?url=https://stripe.com" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```bash With screenshot colors
curl "https://api.prefetch.io/brand?url=https://stripe.com&screenshotColors=6" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```bash Every color source
curl "https://api.prefetch.io/brand?url=https://stripe.com&screenshotColors=8&css=true&html=true&filterAchromatic=true" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```

```javascript Node.js
const res = await fetch("https://api.prefetch.io/brand?url=https://stripe.com", {
  headers: { "X-API-Key": process.env.PREFETCH_API_KEY },
});
const { data } = await res.json();

console.log(data.brand.colors.brand_colors[0].hex); // "#635BFF"
console.log(data.brand.logos.primary.url);
console.log(data.brand.fonts.families);             // ["Sohne Var", "SF Pro Display"]
```

```python Python
import os, requests

r = requests.get(
    "https://api.prefetch.io/brand",
    params={"url": "https://stripe.com"},
    headers={"X-API-Key": os.environ["PREFETCH_API_KEY"]},
)
brand = r.json()["data"]["brand"]
print(brand["colors"]["brand_colors"][0]["hex"])  # "#635BFF"
print(brand["logos"]["primary"]["url"])
```

</CodeGroup>

## Color options

By default you get the brand palette. Add options to pull colors from more places:

| Parameter | Adds | Lands in |
|---|---|---|
| *(default)* | The logo's and favicon's colors, and the brand colors the page sets itself (`theme-color`, the header, the primary buttons). Chromatic colors first, white, black and greys after. | `brand.colors.brand_colors` |
| *(default)* | The color each role uses on the page: `primary` and `secondary` button fills, `background`, `text` and `link` | `brand.colors.roles` |
| `screenshotColors=6` | N dominant colors from a screenshot of the page (2–12) | `brand.colors.screenshot_colors` |
| `css=true` | Colors defined in stylesheets | `brand.colors.code_colors` |
| `html=true` | Colors defined in HTML attributes | `brand.colors.code_colors` |
| `javascript=true` | Colors defined in JavaScript | `brand.colors.code_colors` |
| `filterAchromatic=true` | Drops near-white, near-black and grey results | |

`css`, `html` and `javascript` all feed one `code_colors` map, keyed by the nearest named color rather than by source. Groups are ordered by how much the site uses them. Every spelling of one color (`#000`, `rgb(0,0,0)`, `rgba(0,0,0,.25)`) is one entry, and transparent values are left out.

Logo and favicon colors are the exact color most of their pixels have. When that's within ΔE 6 of a color the page renders, it snaps to the page's color, so a brand color the CSS sets (`#632CA6`) comes back as that hex rather than a near neighbor.

`social_links` come from the page's links, then its JSON-LD `sameAs`, `rel="me"` and Twitter card tags. If none of those name a profile, Prefetch reads the footer after scrolling it into view. Each link is the profile's plain URL, without tracking parameters.

`/brand` takes camelCase parameters. Batches and MCP take the snake_case spelling (`screenshot_colors`).

## Design tokens

`brand_colors` tells you what a brand's colors are. `designTokens=true` tells you what each one is **for**, read from the page as it renders:

- **Colors by role:** `primary` (the most prominent button's fill), `secondary`, `background`, `text`, `heading` and `link`, plus whether the page is `light` or `dark`
- **Typography:** body and heading font stacks, weights, line height, and the h1 to h3 and body sizes
- **Components:** the primary and secondary button (fill, label color, border, radius, weight) and the first text input
- **`border_radius`:** the primary button's rounding, a good guide to the whole site's

The block lands at `brand.design_tokens`. It's best effort: a field the page gives no reliable answer for is `null`. Requests with `designTokens=true` are always read live, never from curated data.

```bash
curl "https://api.prefetch.io/brand?url=https://stripe.com&designTokens=true" \
  -H "X-API-Key: $PREFETCH_API_KEY"
```
